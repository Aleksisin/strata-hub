### 1.3 Знания, меняющие конфигурацию будущих серий

- **Марафон-рассуждение — свойство базы**: Swift-evals: reasoning_tokens p90 = 27.7K, max = 100K даже в бенчмарке; наш инцидент n_gen ~6900 → таймауты. Противоядие: `--reasoning-budget N` (серверный жёсткий кап).
- **preserve_thinking раздувает контекст**: прошлые thinking-блоки остаются в истории каждого раунда агентного цикла (наш сервер prints «preserving reasoning enabled by default»). Кандидат: `--no-reasoning-preserve`.
- **Draft-головы убивают сравнимость текстов**: одни веса + MTP3 vs DFlash2 = 0/118 идентичных текстов (RU-исследование); MTP вывод расходится с обычным на 92–100% (insidepc). ⇒ Seed-серии только без-MTP; спекуляцию сравнивать агрегатами.
- **Специализация спекуляции по контексту**: MTP2 @4K на 12 ГБ = +73% (+0.8 ГиБ); DFlash2 @4K = +0.3% (+1.4 ГиБ), но у arczhi DFlash2 на коде @262K = +51%. MTP — короткий контекст, DFlash2 — длинный; оба требуют VRAM, которую даёт только tierkv/KVMem/патч.
- **Imatrix-ловушка**: русско-калиброванная imatrix ухудшила русский на 20–36% при KL, говорившем об обратном. Проверка репаков — на реальных текстах, не по KL.
- **Кванты не вредят русской грамматике**: ошибки 18–20/10K независимы от битности (4.5–8 бит), RuBLiMP 94.6–95.1%; ошибки принадлежат базе. Наши APEX-I + q4_0 KV — безопасны для русского.
- **Pi не пересылает reasoning-параметры в llama.cpp** (upstream #5917 not_planned) → турнирный Pi бьёт в серверный дефолт effort (у нас low) — честно для всех harness.
- **Официальное сэмплирование thinking-режима**: temp 1.0, top-p 0.95, top-k 20 (не 0.6 из гайдов 3.5/3.6). Наш раннер сознательно temp 0.2+seed 42 — не менять в сериях.
- **Бар верификации движков** (feveromo): back-to-back A/B одной сессии, KLD vs reference (PPL ratio ≤1.0014, 98% top-token), test-backend-ops 18 504/18 504, bit-identical replay, секция «проигравшие кандидаты». Плюс byte-identical logits-оракул (SHA-256) из qwen38-in-c.
- **MTP state bug**: llama.cpp #27296 (cross-request state) — даже feveromo иногда отключает MTP (`--spec-type none`).

### 1.4 Физика нашего VRAM-бюджета (16 ГБ, почему спиллило)

Веса 10.41 ГиБ + mmproj 0.49 + KV q4_0@131K ≈ 2.25 (64 КиБ/токен f16 × 28%) + состояние/буферы ~1.5 + резерв 1.0 ≈ **15.2 из ~15.5 ГиБ**. Без MTP — впритык (чистый бут без fit-warning подтверждён 05.11). Draft-MTP добавляет свой KV на полный контекст + compute-буферы (замеры: +0.8 ГиБ @4K, +3 ГиБ @8K) → +1.5–3 ГиБ не помещаются → WDDM-спилл (Windows молча уводит в RAM; Linux отдал бы OOM) → 3.8 т/с. **Три независимых решения**: (а) сжать буферы/MTP (feveromo-патч), (б) увезти KV в RAM (tierkv/NInfer), (в) сменить формат весов (ExLlamaV3 — вне оси).

### Фаза R0 — дешёвые флаги на текущем stock-билде (первая, без сборок)

Цель: победить марафоны и контекст-блоат без смены движка. Поддержку и семантику
флагов проверить НА НАШЕМ b11985-mix, не только по документации master.

Порядок (ревью 05.11 — самая интересная гипотеза первой):
- **R0-1**: `--no-reasoning-preserve` — сокращение накопленной истории. КАВЕРЗНОСТЬ: не обязательно уменьшит историю, если раннер УЖЕ исключает reasoning из передаваемых сообщений. Обязательная верификация — сравнение **фактических сериализованных промптов** (дампить то, что реально уходит на сервер), не только логов сервера.
- **R0-2**: `--reasoning-budget 16384` — кап чрезмерного reasoning (p50 2.7–7K по Swift-данным, 16K = 2–6× запас к медиане).
- **R0-3**: серверный `reasoning_effort medium` vs `low` — качество при другом бюджете рассуждений.
- **R0-4**: лучшая комбинация R0-1/2/3 — совместный эффект.

Главный метрик R0: **рост prompt_tokens по раундам** (не только wall). Протокол: по 3 задачи на вариант (d3-контроль + bf1 + bf4), новый префикс серии (r01-/r02-/r03-/r04-), прод-флаги меняются ТОЛЬКО на время варианта, рестарт-протокол python-драйвера.
Критерий: 3 задачи = **smoke и отбор, НЕ финальная приёмка** — уверенный вывод о качестве даёт только последующая полная серия. Вариант, прошедший smoke без регрессов и с сниженным ростом промпта, вносится в freeze следующей большой серии, где и подтверждается.

Протокол допуска — ВОРОНКА (ревью 05.11: полная серия только для прошедших):
1. **Совместимость**: загрузка именно нашего APEX-I GGUF, корректный tool-calling, отсутствие memory spill.
2. **Корректность вычислений**: сравнение logits/KLD/PPL со stock на фиксированном корпусе и **нескольких длинах контекста**. PPL ratio ≤1.0014 — это допуск из эксперимента feveromo, не универсальный стандарт: использовать как строгий ориентир и дополнительно смотреть **распределение отклонений** и реальные случаи расхождения tool-calling.
3. **Производительность**: парный replay реальных сессий при одинаковых длинах и одинаковом GGUF (наш стенд, наш промпт-поток — не чужой replay).
4. **AgentBench subset**: 3 задачи — успешный контроль (d3), сложный bugfix (bf1), длительная задача с большим контекстом.
5. **Полный AgentBench 10/10** — только для прошедших ступени 1–4 (новый префикс eng1*-, заморозка-манифест на каждый бинарь: SHA256, флаги, VRAM-пик).

VRAM-проверки — три, вместо одного порога (порог «free ≥1 ГиБ» может отвергнуть даже рабочий stock — наш бюджет 15.2 из 15.5):
- загрузка **без нежелательного CPU-offload** (нет слоёв на CPU в логе бута);
- **отсутствие роста shared GPU memory** под нагрузкой;
- **отсутствие резкого падения скорости** при росте контекста (tg-траектория по логу).

Плюс A/B/B/A порядок против stock для контроля дрейфа.
- Метрики: **успешные проверенные задачи / GPU-час** (первичная), wall/задачу, decode-медиана из лога сервера, first_verification_pass rate, peak VRAM.
- Стоп: кандидат не влезает чисто в 131K (после 3 задач спилл-симптомы) → в отказ или понижение ctx; гейт качества провален → в отказ; 2+ infra подряд → стоп серии, разбор.

  контент-гэп, на котором промахнулись и Pi, и dsh в турнире) и УКРУПНИЛ

- **bf2 и тройка — сравнение только по исходам**: траектории разошлись до

  KV-кэша сервера (r02full-bf2 шла 7-й задачей на своём сервере, b8192-bf2

## 5. РЕВЬЮ ОПЕРАТОРА 05.11 (вечер) — GO на исследование оси движка, правки внесены
